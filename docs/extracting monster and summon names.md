# Extracting data from BTL\FF5_BTL.BIN

I applied the same text encoding from the dialogue on BTL\FF5_BTL.BIN and found lots of text strings:

Monster names were found starting in `BTL\FF5_BTL.BIN` at `0003BBFC` as a continuous array of encoded text with no terminator characters.

Directly above it, starting at `0003B8E0`, is an index table:

00 00 06 00 
10 00 19 00 
22 00 2B 00 
31 00 38 00 
42 00 4C 00 
54 00 5E 00 
67 00 6D 00 ...


After parsing, each pair of bytes in this table becomes a **16-bit little-endian offset**, forming a list of byte positions into the text blob.
These offsets define where each string begins and ends inside the blob:
```
string[i] = blob[offsets[i] : offsets[i + 1]]
```
This means the index table does not store text itself—it acts as a **pointer directory**, mapping each entry to a slice of the blob.



```python
def parse_hex_bytes(s: str) -> bytes:
    return bytes(int(x, 16) for x in s.split(Empty))

def parse_offsets(s: str) -> List[int]:
    raw = [int(x, 16) for x in s.split(Empty)]
    # 16-bit little endian
    return [raw[i] | (raw[i+1] << 8) for i in range(0, len(raw), 2)]

def parse(blob, offsets):
    out = []
    for i in range(len(offsets) - 1):
        chunk = blob[offsets[i]:offsets[i+1]]
        text = "".join(byte_to_char.get(b, "_") for b in chunk)
        out.append((i, text))
    return out

offsets = parse_offsets(index_table_hex)
blob = parse_hex_bytes(byte_blob_hex)


output = parse(blob, offsets)

for k,v in output:
    print(v)
```

This format uses a classic pointer table + string blob structure:

The index table stores offsets into the blob
The blob contains all strings back-to-back
Strings are reconstructed by slicing between consecutive offsets
Each byte is decoded using a custom encoding table

This effectively reconstructs the game's internal string lookup system externally.

I managed to do much of the same for other strings within the file. Pretty much all of the text that might appear in battle one-way or another is in this file. Use the dialogue
tbl to find the block you're looking for then the string start and end table should be right before it, plus 00 padding prefixed one or both.

# Monster Stat Block
00004600 is where the Monster stats start. They are in the same order as in SNES FFV if I reecall correctly, each monster stat block is 32 bytes:
AGI|STR|ATKX|EVA|DEF|MAG|MAGDEF|MAGEVA|HPLO|HPHI|MPLO|MPHI|EXP|GIL|
???|???|????|???|???|???|??????|??????|????|????|????|????|???|LVL|

|--LO|--HI| refers to the low and high bytes, they're stored as 16-bit unsigned integers like you'd expect.

As opposed to what some guides online may tell you, ABP is not based on monsters but the monster formations.
